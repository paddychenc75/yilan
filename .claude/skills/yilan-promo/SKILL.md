# 一览的新版介绍视频和分享文案

产出三样东西，都只放在本机，不进 git：介绍视频（MP4）、封面图（PNG）、各平台文案。先给负责人看分镜，确认后再导出视频，不要一上来就导出。

## 放在哪里

- 这个版本的全部文件放 `changes/<版本号>/promo/`（`changes/` 已在 `.gitignore` 里，不要 `git add -f`）。
- 第一版（v0.2）的成品在 `design/intro-video*`，是可以直接复用的样板。做新版本时把它们复制到 `promo/` 再改，不要改 `design/` 里的原件：
  - `intro-video.html`：分镜页，画面是时间的函数（`render(t)`、`window.seekTo(t)`，网址加 `?bare&t=秒` 只出画面）。舞台固定 1920×1080。
  - `intro-video-export.mjs`：逐帧导出。`node intro-video-export.mjs <html 的绝对路径> <输出.mp4>`，用无头 Chrome 取帧喂给 `ffmpeg`（30 帧，libx264）。
  - `intro-video-music.py`：用 numpy 合成配乐和音效，`python3 intro-video-music.py out.wav`。里面的段落时间点要改成和新分镜一致。
  - `intro-video-cover.html`：封面生成页，`?only=x43|xhs|wide` 配合对应的 `--window-size` 截图。
  - `intro-video-photos/`：21 张 CC0 照片和 `CREDITS.md`。
- 成品另外复制一份到 `~/Downloads/`，用中文文件名（如 `一览 v0.3 介绍视频.mp4`、`一览封面-小红书视频4比3.png`），并把完整路径告诉负责人。

## 第一步：定内容

1. 读 `docs/release-notes/<版本号>.md` 的中文段，这是「这个版本有什么」的唯一依据。更新说明里没有的功能不要讲。
2. 从「新功能」里挑 3 到 5 个最容易一眼看懂的做成镜头，「改进」「修复」一般不单独成镜头。
3. 写分镜表给负责人确认：每个镜头的起止时间、画面、字幕。总长 30 到 45 秒。结构固定为：
   - 开头（约 4 秒）：一句话说清这是什么。第一版的口号是「打开一张，看完整个文件夹」；新版介绍用「一览 v<版本号>」加这个版本最大的一个卖点。
   - 中间：每个功能一个镜头，5 到 7 秒，字幕一行，写用户能做什么和按哪个键。
   - **片尾（必须有，不少于 4 秒）：说明怎么下载**，见下一节。

## 片尾必须说明下载方式

文案里不能写下载方式（见第五步），所以片尾是唯一告诉观众去哪找的地方，要让人看完就知道。画面上按顺序出现这几行，字要够大，停留够久，能让人截图：

1. 图标和名字：「一览 Yilan」，旁边写「开源 · MIT」。
2. 「在 GitHub 搜索 `paddychenc75/yilan`」。搜索词用等宽字、加底色框，是整个画面最醒目的一行。
3. 「进入仓库 → 右侧 Releases → 下载 `Yilan-<版本号>.zip`」。
4. 系统要求：「需要 macOS 15 或更高版本」（以当前 `README.zh-CN.md` 的系统要求为准，每次都去核对，不要照抄这里）。

搜索词固定是 `paddychenc75/yilan`（仓库地址只有这一个，搜出来是唯一结果）。做之前先确认仓库还是公开的、这个版本的 Release 已经发布且附件名对得上：

```sh
gh repo view paddychenc75/yilan --json visibility,licenseInfo --jq '{visibility,license:.licenseInfo.name}'
gh release view v<版本号> --json assets --jq '[.assets[].name]'
```

版本还没发布就先做视频也可以，但要告诉负责人「片尾写的文件名要等发布后才存在」，发布后再核对一次。

## 第二步：画面素材

- **界面画面优先用真实截图**：用 Debug 版加 `--shot-*` 启动参数摆出状态再截窗口（参数说明在 `app/Yilan/App/ShotHooks.swift` 顶部，做法和 README 截图一样）。第一版用的是手画的示意界面，有真实截图后不要再用示意图。如果某个镜头只能用示意图，要在汇报里说明。
- 照片和视频只用公开素材：`design/intro-video-photos/`、`app/Fixtures/sample/`。**绝不用负责人自己的照片。**
- 需要新素材时去 Wikimedia Commons 找，只要 CC0 或公共领域的，逐张核对许可（`LicenseShortName` 是 CC0、`Restrictions` 为空），不要有可辨认的人物，把来源页、作者、许可记进 `CREDITS.md`。请求里用通用的客户端名称，不要带负责人的姓名、邮箱或项目信息。
- 截图里不能露出负责人电脑上的路径或文件夹名（「最近打开」列表、信息面板的「文件夹」一行）。素材放在 `/tmp/Yilan Samples` 这类中性名字的文件夹里再截。

## 第三步：做视频

1. 改好 `intro-video.html` 后，用无头 Chrome 在每个镜头的中间时刻各截一张（`?bare&t=秒`），**逐张看过**：字幕有没有被图片盖住看不清（亮色照片上要加底部渐变）、有没有文字截断或重叠、图片有没有没加载的。
2. 把分镜页和这些截图给负责人看，确认后再导出。
3. 导出画面、生成配乐、合成：

   ```sh
   node intro-video-export.mjs "$PWD/intro-video.html" video.mp4
   python3 intro-video-music.py music.wav
   ffmpeg -y -i video.mp4 -i music.wav -c:v copy -c:a aac -b:a 192k -shortest out.mp4
   ```

4. 配乐响度控制在 -15 LUFS 左右（`ffmpeg -i music.wav -af ebur128 -f null -` 看 Integrated 值），太响就降输出增益。音效要对齐镜头切换的时间点。
5. 导出后用 `ffprobe` 核对时长、分辨率（1920×1080）、有音轨；再从成片里抽 3 到 4 帧看一眼（开头、中间、片尾），片尾那帧必须能看清搜索词。

## 第四步：封面图

三个尺寸，从 `intro-video-cover.html` 出：

| 用途 | 尺寸 |
| --- | --- |
| 小红书横版视频封面（4:3） | 1440×1080 |
| 小红书图文封面（3:4） | 1242×1660 |
| B 站、通用横版（16:9） | 1920×1080 |

封面上写：类别标签「Mac 看图软件」、大标题（新版本写这一版的卖点）、三个以内的功能短语。不写「独立开发」。导出后逐张看，标题不能和界面图重叠。

## 第五步：分享文案

四个平台各一份，直接在回复里用文字给出，方便复制：

- **小红书**：三个备选标题（20 字以内）、正文（短句分行，功能用 ✅ 列出）、8 个左右话题标签。正文里不能放链接。
- **B 站**：标题、简介，简介里带时间轴（`00:00 开头` 这样逐镜头列，时间和成片一致），并注明画面里的照片是 CC0 公开素材。
- **微博 / 即刻 / 朋友圈**：一段话，150 字以内。
- **X**：英文，280 字符以内。

所有文案都遵守：

- 说明这是**开源软件（MIT）**。
- **不写任何下载方式**：不放链接、不放仓库网址、不写「GitHub 搜什么」、不写「去哪下载」，标题、正文、简介、话题标签（不用 `#GitHub`）都一样。平台会把这类内容判定为引流到外部。下载方式只出现在视频片尾的画面里；文案里最多写一句「怎么找到它，视频最后有说明」。
- 写清系统要求（和片尾一致）。
- 不写「独立开发」「免费」，不求 star、不求转发。
- 只写更新说明里有的功能。「秒开」「几乎不用等」这类说法，只有实际测过或 PRD 里有对应指标才用，否则换成平实的说法。
- 新版本的文案开头点明版本号和这一版最大的变化，再列其余新功能；老功能最多用一句话带过。

## 汇报时如实说明

- 哪些画面是真实截图，哪些是示意图。
- 配乐是程序合成的，你听不到，请负责人自己听一遍音量和风格。
- 片尾的仓库和附件名是否已经用上面的命令核对过。
- 成品的完整路径（`changes/<版本号>/promo/` 里的和 `~/Downloads/` 里的）。

## 注意

- 这个技能不发布任何东西：不 push、不发帖、不上传视频。发到社交媒体由负责人自己做。
- 需要 `ffmpeg`、Node（自带 `WebSocket` 的版本）、`/Applications/Google Chrome.app`、Python 的 numpy。缺哪个先告诉负责人，安装前按惯例查安全公告，不装最新版。
